# Фиксированный кандидат и дополнительная проверка территорий

Эта запись сделана после просмотра результатов основного этапа, до вычисления дополнительной проверки. Исходный PROTOCOL.md, старый selection.json и все неблагоприятные результаты сохраняются.

Выявлено: ранний validation, содержащий очень мало календарных целей, выбирает нестабильные модели (в частности, последнее значение для h=6). После накопления 18 месяцев общая Ridge-модель без новостей показала меньшую MAE, чем reference Prophet, на всех трёх коротких горизонтах исходной тестовой выборки. Добавление новостей не улучшает все горизонты, а Chronos не выигрывает автоматически.

**Фиксируем один кандидат**: Pooled Ridge без новостей для h=1/3/6 при >=18 месяцах истории; для более короткой истории seasonal_scaled. Для h=12 сохраняется ранее объявленный damped_trend. Гиперпараметры Ridge и признаки не изменяются. Это выбор после разработки, а не победитель полностью слепого временного теста.

Дополнительная проверка: ещё 100 МО, первый год >=9 наблюдений во всех шести категориях, SHA-256 rank с seed 20261009. Исключены исходные 10 МО и все 50 МО основного сравнения. При одинаковых prefix/target сравниваются кандидат, Prophet auto, seasonal_scaled и Chronos-Bolt-Tiny. Origins 18/21/23 для h=1/3/6; отдельно origin12 для h=12. Обучение по-прежнему использует только прошлое, допускает историю проверяемых МО. Кандидат после этой проверки не переключается, даже если проиграет.

Периоды совпадают с основной проверкой, а первичный полный baseline уже затрагивал эти месяцы. Следовательно, это проверка устойчивости к составу территорий, **не независимый временной holdout и не доказательство переносимости на будущие шоки**. Все результаты, включая ухудшения, публикуются.

В итоговом экспорте применяется фиксированный кандидат. Отчёт отдельно показывает неустойчивый ранний селектор, разработочные результаты кандидатов и дополнительные территории. Новостная модель остаётся честной ablation, а новости дополнительно используются как временной контекст сигналов.
